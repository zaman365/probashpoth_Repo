# Data model

The full entity set is defined as explicit SQL in
`apps/api/src/storage/postgres/migrations/` (§45). The in-memory
development driver stores the same record shapes, defined in
`apps/api/src/storage/records.ts`, behind the same `Storage` port (ADR 0001).

## How the pieces relate

```text
country ──< regulatory_source ──< source_snapshot        (provenance, hashed evidence)
   │                │
   │                └──< rule_version   (versioned, effective-dated, published/draft)
   │                          ▲
   └──< route_version ────────┘        (requirements, risk notices, fee_rule ids)
             │  │
             │  └──< fee_rule ─────────────────┐        (payer, payee, legal basis)
             │                                  │
occupation ──┴──< job ──< organization          │        (employer, recruiter + licence)
                    │                           │
app_user ──< identity_profile                   │
   │  ├── migration_passport ──< passport_fact  │        (shared, versioned facts)
   │  ├── work_profile                          │        (independent Work evidence)
   │  ├── academic_profile                      │        (independent Study evidence)
   │  ├── readiness_assessment ──< preparation_task
   │  ├── recommendation_set ──< alert_subscription
   │  │                                         │
   │  ├──< consent ──< delegation               │        (family co-pilot, revocable)
   │  ├──< document ──< document_share          │        (scoped, expiring, audited)
   │  └──< mobility_case ──┬──< case_task       │
                           ├──< case_milestone  │        (gates settlement)
                           └──< cost_plan ──< cost_item ─┘
                                                  │
                                     payment_intent ──< provider_transaction
                                                  │
                                     journal_entry ──< journal_line ──> ledger_account
```

## Invariants enforced in the schema

- **Journal entries and lines are immutable.** `DO INSTEAD NOTHING` rules block UPDATE
  and DELETE; corrections are new reversing entries (ADR 0004).
- **Journal line amounts are positive** (`CHECK amount_minor_units > 0`); direction
  carries the sign.
- **Money is `(minor_units BIGINT, currency CHAR(3))`** everywhere. No floats (§83).
- **Audit events are immutable** and indexed by actor and by resource.
- **A complaint can never be deleted**, by anyone, including the organization
  complained about (§76.8).
- **Publication status is constrained** to `draft | review | published | withdrawn` on
  both rules and routes; only `published` versions can drive a user-facing answer.
- **Idempotency keys are unique** on `payment_intent`, `provider_transaction` and
  `journal_entry`.
- **National identifiers are ciphertext columns** (`nid_ciphertext`,
  `passport_no_ciphertext`) — plaintext identifiers never get a column to live in.

## Identifiers

UUIDv7, generated by the application (`@probash/domain`'s `uuidv7`), so identifiers
sort by creation time and keep large audit and event tables index-friendly (§42.6).
Public job identifiers are a separate, human-readable, non-PII format:
`BD-QA-2026-00482915`.

## What the in-memory driver does not model

Transactions, row-level security, partitioning, and full-text search. Those arrive
with the PostgreSQL adapter; the port exists so that adapter is the only thing that
has to change.
